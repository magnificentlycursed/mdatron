# Changelog

All notable changes to mdatron will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

mdatron is descended from Schematron (ISO/IEC 19757-3). It is **not** related to
the TRON blockchain.

## [Unreleased]

### Added
- **link check family** (#145) — one of the two reference check families (with marker, #147): inline body links in governed markdown are resolved against the working tree. A link to a relative path that is not present blocks (`MDATRON-E0110`, dead-link-target); an existing markdown target — or the same document — whose `#fragment` matches no heading blocks (`MDATRON-E0111`, dead-anchor, fragments resolved with the GitHub heading-slug algorithm). Activation is per-route (`links: true` in `routes.yaml`), mirroring the citation family — so link-checking is an explicit choice and historical corpora stay archival. Link targets resolve **document-relative** (CommonMark/GitHub semantics): a target is relative to the *containing file's directory*, so `[api](api.md)` in `docs/guide.md` is `docs/api.md` and a one-level `../README.md` that stays in-tree is legitimate. This is a deliberate refinement of the family-wide confinement discipline — unlike a citation's categorical `..` refusal, the link family collapses `..` lexically against the containing directory and refuses only a target that escapes *above* the root (`E0011`), is absolute (`E0010`), or resolves through a symlink (`E0012`) — the same confinement contract, decided on the resolved path. Headings inside fenced code blocks are not anchors, and links inside fenced code blocks **or inline `code` spans** are examples (not resolved — #154, found by the lychee reference-arch review; the shared `markup::inline_code_ranges` masks inline code, distinct from a code-catalog token which stays a real citation when backticked). External links (any URL scheme; the engine never reaches the network), reference-style links, image links, and setext headings are deferred in the first cut. Explain pages `MDATRON-E0110`/`E0111` ship with the codes; DESIGN § Seven check families and the README are amended.
- **marker-line reference check family** (#147, vsdd GH#20 P3) — the name-anchor sibling of `citations`/`links`: a governed body line matching a route's declared `marker_rules` pattern names a reference whose captured `<name>` must resolve to an existing element in a rule-config-named target document. A reference resolving to nothing blocks (`MDATRON-E0112`, dead-marker-reference). The `element` class is configurable — `heading` or `list-item-bold-name` (the leading `**bold**` name of a `- ` list item; `frontmatter-key` reserved) — so the primitive serves any by-name reference shape. Resolution is **name-equality** with a trailing `.` on the target tolerated (vsdd's live shape: `- **Slice 1 — …the guardrail.**` ← `Provenance: Slice 1 — …the guardrail`), deliberately *not* slug-based. The `target_doc` is named in the rule config (not derived from `governed_by`, not carried per line), project-root-relative, and confined categorically like a citation path (`E0010`/`E0011`/`E0012`); an optional `target_section` scopes resolution to a heading's span. Activation is per-route (`marker_rules`). Built on the shared `markup` reference-scan core extracted for the citation/link/marker convergence (the rule-of-three refactor, surfaced by the Schematron lineage audit). Explain page `MDATRON-E0112` ships with the code.
- **section-scoped content pins** (#146, vsdd GH#20 P2): a pin may carry an optional `section` (a heading, e.g. `"## Decomposition (phase 1c)"`) to scope its sha256 to that **heading-delimited span** — from the heading line through just before the next heading of the same or higher level (fence-aware) — instead of the whole file. An edit outside the pinned section no longer trips the pin; a `section:` whose heading cannot be located is `MDATRON-E0063` (pin-section-not-found), loud rather than silent. `mdatron pin --update` recomputes section hashes the same way. **Additive & backward-compatible:** `section` is optional (absent = whole-file, unchanged) and omitted from serialization, so existing `pins.yaml` records stay byte-identical; no envelope change. Built on a shared `markup::section_span` primitive (the heading-span twin of the marker family's section gating — the citation/link/marker/pin convergence). Explain page `MDATRON-E0063` ships.
- **adopter-namespace code-catalog integrity** (#148, vsdd GH#20 P4): declare an adopter code namespace in `.mdatron/code-catalogs.yaml` (`{ namespace, comprehensive, codes }`) and every adopter code token cited in the governed corpus (e.g. a `VSDD-`-namespaced code) must resolve to a declared entry — the adopter-side twin of mdatron's own every-code-resolves-in-explain tripwire. Under a `comprehensive` catalog (SARIF's `isComprehensive`, which licenses the hard gate) a cited token that is not declared blocks (`MDATRON-E0113`, orphaned-adopter-code) — the fix for codes left dangling after a defining doc is sunset. The catalog is keyed on the ownership **prefix** (Ruff's `Linter` model — codes owned by a prefix, not a numeric range); the **detector is deliberately broader than the legal grammar** (a namespace prefix on a word boundary followed by a digit-bearing run), so a mistyped/unknown class is caught by the resolver rather than silently skipped — the `codes:` list, not the detector, is the closed legal set. A new `code_catalog` `families` member (additive, folds into the unpublished 0.6.0). Built on the shared `markup` scan spine (the fourth reference-resolution check — citation/link/marker/code). Shaped by the SARIF + Ruff reference-arch review and vsdd-cli#27 (SO-ratified: comprehensive + error). Explain page `MDATRON-E0113` ships.
- **section-structural check family** (#157, vsdd GH#20 P5): declarative **count** and **disjointness** assertions over markdown body sections, declared in `.mdatron/section-rules.yaml` — the body-content leg of #149 (the DSL frontmatter half shipped separately), delivered as a fixed-semantics check on the shared `markup`/section spine rather than an extension of the body-content-gated rule DSL. A *count* rule (`{section, element, match, count}`) counts the `element`-level headings in a section's span whose line matches `match` and asserts a `count` predicate (`>= 1`, `== 1`, …) → `MDATRON-E0120` (section-count-violation). A *disjoint* rule (`{disjoint: [op, op]}`) extracts an id set from each of two sections and asserts they share none → `MDATRON-E0121` (section-ids-not-disjoint). The id extraction is **element-scoped** (H3 heading text, or a `- **bold**` bullet lead) — *never a full-span scan*, so a body mention of an id can't cause a false overlap (the load-bearing rule pinned on vsdd GH#29). Mechanizes acceptance checks that were grep-convention ("at least one open-phase H3 in `## Requirements`", "phase ids disjoint between two sections"). A new `section` `families` member (additive, folds into the unpublished 0.6.0); codes reserved `E0120`–`E0129`. Explain pages `MDATRON-E0120`/`E0121` ship. Semantics confirmed on vsdd-cli#29 against the live build-plan.
- **Envelope `mdatron_output_version` `2.1.0 → 3.0.0` — MAJOR (#145/#147/#148/#157).** The `families` object gains the **required** members `link` (#145), `marker` (#147), `code_catalog` (#148), and `section` (#157), and becomes **forward-extensible** — its `additionalProperties` moves from `false` to the `FamilyActivity` shape, so a family added *after* this release is an additive member (a MINOR from here) and a consumer must tolerate unknown family keys. A closed-object required-field addition is breaking per the versioned-contract SemVer rule, so the new members plus the reshape ride one deliberate MAJOR. (0.6.0 is unreleased, so #145/#147/#148 fold into the **same** 3.0.0 envelope — the published jump is a single `0.5.0 → 0.6.0` carrying all three.) The published schema (`schema/mdatron-output.schema.json`), its `$id`, `OUTPUT_VERSION`, the golden code-catalog, and the contract-stability tripwires move in lockstep. The crate moves `0.5.0 → 0.6.0`.

### Fixed
- the vocabulary family's prose checks now **skip inline `` `code` `` spans** (#158, vsdd GH#28 Gap 2): a letter-plus-number cluster (`E0091`) or a register anti-pattern (`E0093`) *quoted* in an inline code span — a historical commit subject, or naming a deprecated term as `` `chassis` `` to *reference* rather than *use* it — is a citation, not a use, and no longer false-positives. Reuses the same `markup::inline_code_ranges` masking the link check applies (#154). Symmetric with the link/citation checks (a term in backticks is a reference), and deliberately **opposite** the code-catalog check (where a backticked `` `VSDD-W0070` `` is a real formatted citation that still resolves-or-orphans). Coinage (`E0090`), reserved-word (`E0092`), and numeric-claim (`E0094`) checks are unchanged; fenced code blocks (a separate class) are not yet exempted.
- **structured reference-IDs are exempt from `E0091` by default** (#159, vsdd GH#28 Gap 1): the invented-label-scheme check flagged spec **reference-IDs** — `REQ-10`, `AC-4`, `ADR-7`, `RFC-2119`, `Q1` — as coinages (327 of 336 E0091 findings on the first consumer's `.design/` corpus were this class). These are references to numbered spec items under decades-old conventions (IEEE/ISO requirement IDs, ADR, RFC), not invented schemes. A curated engine **default allow-set** (`^REQ-\d+$`, `^AC-\d+$`, `^ADR-\d+$`, `^RFC-\d+$`, `^Q-?\d+$`) is now **unioned** with the consumer's `label_schemes.allow` whenever the cluster scan is active, so spec corpora validate out of the box and a consumer supplies only its *local* schemes (e.g. `^C\d+$`). The default set is deliberately conservative — multi-character, well-known prefixes only; ambiguous single-letter forms (`C8`, `T3`) stay consumer-opt-in to avoid masking a genuine coinage — and it **never newly-activates** the scan: a consumer who did not opt in via a non-empty allowlist sees no change, so this can only *remove* false positives, never add findings. Operator-ratified (default-allow-set-plus-template over a detector token-class split or template-only). `E0091`'s explain page, DESIGN § vocabulary, and the README document the default set + extension template.

First crates.io release (#48) — an early-0.x public debut (per the DEF1 ruling).
Ships everything accumulated since the `v0.4.0` tag, hardened by a full pre-publish
adversarial roast: **26 findings across 3 iterative rounds, all fixed** — three
HIGH among them (a JSON-Schema `pattern` **ReDoS**, and two diagnostic

to a **linear-time** regex engine; DEF4 project-root-relative **and**

`--deny-warnings`/`--strict` hard-gate flag; enforced input resource bounds; a
`cargo-deny` supply-chain gate; and the published-schema `$id` moved off an
unowned domain to the project's GitHub namespace. **Envelope:**
`mdatron_output_version` moves **2.0.0 → 2.1.0** — a MINOR bump (the additive
`pipeline_error.kind: "bound_exceeded"`). Accordingly the crate moves `0.4.0 →
0.5.0` (new features + the additive envelope; a pre-1.0 minor per SemVer).

### Added
- numeric-claims check family: flag numeric literals in body prose restating frontmatter facts (consumer raise; drift class paid 3x by vsdd-cli) (#79)
- v1.0: documentation (#49)
- phase-3 adversarial review (The VDD Roast): full-app pre-publish roast + polish + docs/README, before crates.io #48 (#122)
- input resource bounds are enforced with a loud diagnostic, and the `verify --json` envelope's `mdatron_output_version` moves **2.0.0 → 2.1.0** to carry the new failure kind (#124, roast SHO1): a per-file byte cap (`MAX_FILE_BYTES`, 8 MiB), an aggregate-snapshot byte cap (`MAX_AGGREGATE_BYTES`, 64 MiB), and a structural-nesting cap (`MAX_STRUCTURAL_NESTING`, 256) each exceedance a `pipeline_error` with the new `kind: "bound_exceeded"`; the DSL expression-nesting cap (`MAX_EXPR_DEPTH`, 256) surfaces as `kind: "expr_parse"` (a bounded `ParseError`, not the stack-overflow abort it prevents). Together these replace silent degradation, unbounded memory, and an uncatchable parser abort. The `bound_exceeded` value is **additive** to the closed `pipeline_error.kind` enum, so the envelope moves by a **MINOR** (`2.0.0 → 2.1.0`) per the versioned-contract SemVer rule (§ Diagnostics are a versioned contract); the published schema, `OUTPUT_VERSION`, and `E0080`'s explain page are updated in lockstep. (This entry documents a contract change that shipped after the 0.4.0 tag but was previously unrecorded — a gap the pre-publish re-roast caught, D1; the expr-depth `kind` was itself corrected in round 2.)
- `mdatron verify --deny-warnings` (alias `--strict`) escalates a warnings-only run to a failing exit (#121, requested by vsdd-cli mdatron#1): an otherwise-clean run (exit `0`) that carries warnings now exits `1`, so a hard-gate consumer can fail on warnings without parsing the JSON envelope. Errors (`1`), pipeline failures (`2`), and a genuinely clean run (`0`) are unchanged; the escalation is purely `0 → 1` when `summary.warning_count > 0`.

A cut already at a word gap keeps its final word; a single token wider than the whole budget has no interior space to retreat to and still takes the hard char-boundary cut (word-boundary is a preference, not a requirement). The 512-byte cap and the quoted-value-ahead-of-prose priority (#115) are unchanged.

### Fixed
- the `verify --json` envelope now renders every path with `/` separators, so the same repository produces a **byte-identical** envelope on Unix and Windows (#136, DEF4 cross-platform reproducibility follow-up): a `PathBuf` renders with the OS separator (`.mdatron\schemas` on Windows), which broke the machine-diffability the relative-path work established. `Location`'s serialization (every finding's `location.file`), the DSL `$file.path`, and the `pipeline_error` config-path messages now normalize the OS separator to `/` (a no-op on Unix, where a literal backslash in a filename is preserved). TTY/compact rendering keeps native separators — a local, human view. Red gate: `location_serializes_with_forward_slashes`.
- `pipeline_error.message` is now guaranteed host-layout-free for **every** load-path failure (#142, pre-publish re-roast round-3 A): round 2 relativized the specific messages it found, but round 3 showed the leak was broader — a malformed **config/pin/vocabulary/route** file produces a `cannot parse '<abs>'` `Config` message that `relativize_paths` cannot reach. A chokepoint in `cmd_verify` now strips any project-root prefix from the final `pipeline_error.message` (both the original and canonicalized roots, trailing-separator match), a completeness guarantee no per-source fix can make for future messages. Also (round-3 B): the schema `pattern` interpolated inline into an `E0050` message is now escaped (Cc ∪ Zl/Zp) via a shared `escape_inline` helper, closing the last raw-inline surface in `describe()` for partition parity with `at_pointer`/`diagnostic.rs`. Red gates: `pipeline_error_message_relativizes_a_parse_error_path`, `pattern_line_separators_escaped_in_message`.
- `pipeline_error.message` no longer leaks absolute host paths on the three most likely pipeline failures (#140, pre-publish re-roast round-2 A1/A2): the round-1 DEF4 completion (#134) relativized the `VerifyError` `{path}` variants but the path-carrying *free-form* messages still leaked — a **missing** `.mdatron/config.yaml` (the most common failure) and a **globless** config now name the config relatively at the source, a `glob` per-entry read error relativizes the failing path, and an index-build IO/parse error carries the root-relative source path. The JSON envelope's `pipeline_error.message` is now host-layout-free and cross-machine-reproducible across the common failure classes. (A round-2 review also corrected the `catastrophic_pattern_matches_in_linear_time` test's docstring — B2 — which overclaimed a linear-vs-backtracking discrimination the test does not make; the load-bearing linearity guard is the fancy-feature rejection test.)
- roast round-1 low-severity hardening (atomic writes + diagnostic rendering): `atomic::write` now opens its sidecar temp `O_EXCL` (`create_new`) with a retrying attempt counter, so a temp-name collision (two runs in one clock tick, a coarse-resolution clock) retries with a fresh name rather than silently truncating a colliding temp (A3); its module doc records that a Windows rename can fail loudly on a sharing violation with the target intact (B3) and that a crash-leftover temp is harmless (A2). In diagnostic rendering, `verify --compact` no longer emits a dangling `" — "` for a content-free (empty/all-whitespace) message (A4), and a quoted region's `label` is control-char-escaped (Cc ∪ Zl/Zp) in both the TTY and compact forms so a pattern-derived label cannot forge an unprefixed line (B4).
- DEF4 relativization now covers the three remaining envelope path-carriers a pre-publish re-roast found still leaking absolute host paths (#134, roast round-1 A1/B1/B2): `pipeline_error.message` on a failed pipeline (the `VerifyError` `{path}` variants are relativized against the canonicalized root before the message is built), the DSL `$file.path` (now project-root-relative, matching `location.file`), and the `E0010`/`E0011` confinement-escape findings (now anchored at `.mdatron/config.yaml` with the escaping path carried as prefix-marked adopter content, since an escaping path is by definition outside the root and cannot be relativized). The DEF4 invariant test is strengthened to exercise all three.
- every diagnostic `location.file` path in a `verify` run is now project-root-relative, closing a host-layout leak and a cross-machine reproducibility gap (#131 SO ruling / DEF4): walked-file findings were already relativized, but project-level findings (W0047 schemas dir, W0046 config glob, vocabulary) emitted absolute host paths (e.g. `/Users/you/proj/.mdatron/schemas`) via `project_root.join(...)`, leaking the host filesystem layout into the JSON envelope and making two machines' outputs non-diffable. A single normalization pass in `verify::run` strips the project root from every finding's path before the (now relative-keyed, equally reproducible) sort; it is a no-op on an already-relative path. This is impl compliance with the standing DESIGN contract (§ Agents are the first consumer: "file paths rendered relative to the governed tree root"), not a new envelope shape — no version bump.
- diagnostic-surface consistency fixes surfaced by the pre-publish roast (#126, SHO6/8/9/11): (SHO6) `verify --files` help no longer contradicts the shipped refuse-without-jurisdiction behavior; (SHO11) `verify --json` help cites the binary's own published schema rather than a dead `../vsdd-cli/` path; (SHO8) the `MDATRON-E0012` name is canonicalized to `symlinked-component-refused` so the explain page, the golden code-catalog, and the runtime `Finding.summary` all agree (the divergence previously passed CI); (SHO9) the `E0080` explain page and DESIGN § Init no longer overclaim what `mdatron init` scaffolds — corrected from "route/registry/pin directories" to the actual `schemas/`+`patterns/` dirs plus single-file families.
- `pins.yaml` and the managed-partition manifest are now written atomically (#126 DEF8, roast defer-bucket): both are rewritten in place (a `pin --update`, an `init` repair), and `std::fs::write` truncates the target before writing, so a crash, full disk, or `SIGKILL` mid-write left a half-written governance file. A new `atomic::write` helper writes to a same-directory temp file, fsyncs it, then renames it over the target — atomic on the same volume on Unix (`rename(2)`) and Windows (`MoveFileExW`+`MOVEFILE_REPLACE_EXISTING`) — so a reader observes either the whole old file or the whole new one, never a partial. All production `init`/`pin` writes route through it; a failed write leaves the target untouched and no temp residue.
- a declared `schema_class` that nothing serves is no longer silently clean under a **present-but-empty** `.mdatron/schemas/` directory (#111, answered by vsdd-cli mdatron#1): `MDATRON-W0045` (schema-class-unrouted) previously fired only when some validation infrastructure existed, so an init'd project whose `schemas/` and `patterns/` are both empty — a `schema_class` file whose `.json` was never added — exited `0` with no finding, the same silent-false-clean class W0045/W0047 exist to catch. W0045 now fires whenever the schemas directory is **present** (empty or not) and the declared class is unrouted; a **missing** directory remains the project-level `MDATRON-W0047`'s job, so the two never double-report the same file. Fresh-init-clean is preserved: a file with no `schema_class` declares no intent to be validated and stays silent. `verify_file` takes the dir-present signal; the `no_adopter_data_runs_with_all_families_inactive` invariant is updated (the declared-class file now warrants the warning, families still all inactive).

### Security
- the JSON pointer interpolated into a schema-validation (`E0050`) message now escapes the Unicode line/paragraph separators U+2028/U+2029, not just the C0/C1 controls (#140, pre-publish re-roast round-2 B1): a contributor-controlled frontmatter **key** carrying a raw U+2028 previously survived inline in the engine-authored message, forging an unprefixed line — regressing the #125 rendering partition that already hardened `diagnostic.rs`. `at_pointer` now matches the ratified partition (Cc ∪ {U+2028, U+2029}), closing the last inline-adopter-content break surface.
- CI now runs `cargo deny check bans licenses sources` over the full transitive dependency tree (#139, roast C4): a `deny.toml` allow-lists the permissive licenses actually present (MIT/Apache-2.0/BSD/Unicode-3.0/BSL-1.0/Zlib/Unlicense/MIT-0), denies unknown registries and git sources, and denies wildcard version requirements — so an incompatible license or an untrusted source in a transitive dependency fails CI rather than shipping silently in an MIT crate that vendors ~140 crates. The `cargo-deny` tool is version-pinned (#141, roast round-2 C1) so the closed license allow-list cannot float to a future release and red the gate with no repo change. Advisories remain with the existing `cargo audit` step (no double-check divergence).
- adopter JSON Schema `pattern`/`patternProperties` now validate on a **linear-time** regex engine, closing a ReDoS surface on the verify gate (#135, roast C1). `jsonschema` is upgraded `0.18 → 0.49` and built with `PatternOptions::regex()`, routing pattern matching through the linear `regex` crate instead of the backtracking `fancy-regex` — so a contributor cannot craft frontmatter that drives catastrophic backtracking against a project's schema pattern, and DESIGN.md's "linear-time engines" guarantee (§ Behavioral contracts) is now actually true for this surface (route/vocabulary already used linear `regex-lite`). **Behavior change:** look-around and backreferences (fancy-regex-only features, unsupported by a linear engine and not needed for frontmatter shape validation) are now **refused at schema compile**. The upgrade also expands the transitive dependency tree by ~18 crates (the 0.49 workspace modularization; see `docs/dependencies/jsonschema.md`); the API migration (`JSONSchema`→`Validator`, `compile`→`build`, `validate`→`iter_errors`, error accessors now methods) is internal. Proven by `linear_engine_refuses_backreference_pattern` and `catastrophic_pattern_matches_in_linear_time`.

## [0.4.0] - 2026-07-29

Ships the vsdd-cli v0.3.0 diagnostic-efficacy review (the "checked-N vs
checked-nothing" audit-signal work, #104). **Breaking**, per SemVer: the
`verify --json` envelope's `mdatron_output_version` moves **1.1.0 → 2.0.0** — a
MAJOR bump because, since the last released envelope (1.1.0, in 0.3.0), `families`
was reshaped from a string enum to a `{state, reason}` object (#107) and each
`quoted[]` region gained REQUIRED `origin`/`trusted` fields under a closed object
(#114); both are rejected by a 1.1.0-schema validator. `pipeline_error` (#112) is
additive. (Development passed through envelope 1.2.0–1.4.0, never released; the
release collapses them into the single honest major bump.) Accordingly the crate
moves `0.3.0 → 0.4.0` (a breaking change bumps the `0.MINOR` position pre-1.0).

### Changed
- a pattern-rule message's interpolation placeholder now renders as `[see: <label>]` rather than `{$self.field}` (#116, vsdd-cli v0.3.0 diagnostic-efficacy review item 8 part 1): the old `{$self.status}` read as an *un-substituted template* (looked like a bug); `[see: status]` reads as a deliberate cross-reference to the labeled quoted block below. The value still rides out-of-line in the prefix-marked `quoted[]` block — never inline in the message (DESIGN §Output; the same forgeable-marking property `trusted:false` protects). The block label drops the `$self.` prefix so it reads as a field name; a collision or repeated reference is numbered (`status [2]`) so each pointer resolves to exactly one block. Per vsdd-cli's ruling relayed 2026-07-29.
- `families` in the `verify --json` envelope is now a **tri-state plus a reason** (#107, vsdd-cli v0.3.0 diagnostic-efficacy review item 4 — "families was unfalsifiable"). Each of the five families reports `{ "state": "active" | "inert" | "inactive", "reason": "..." }`: `active` = data supplied and the check ran this pass; `inert` = configured but did no work (e.g. `vocabulary.yaml` present but `vocabulary_globs` matched no walked file); `inactive` = not configured. The `reason` documents precisely why — resolving the ambiguity where `active`/`inactive` conflated configured-vs-ran (e.g. `vocabulary_globs` set with no `vocabulary.yaml` now reads `inactive` with the clarifying reason). **This reshape (string → object) is the breaking change** that makes the envelope's `1.1.0 → 2.0.0` bump a MAJOR one.

### Fixed
- `verify --json` without `--quiet` no longer also re-renders every finding as human TTY text on stderr (#117, vsdd-cli v0.3.0 diagnostic-efficacy review W4): the machine envelope on stdout is authoritative, so the duplicate stderr rendering (a ~1.7x token cost for an agent capturing both streams, and now that `pipeline_error` is in-envelope, fully redundant) is suppressed under `--json`. Non-`--json` output is unchanged.
- explain-page "See also" references no longer link to `../../DESIGN.md#…`, a path an adopter running the installed binary does not have (and whose `#summary` anchor had drifted for `E0060`) (#117, vsdd-cli v0.3.0 diagnostic-efficacy review W4): they now name the design section in prose (`the mdatron design reference, § …`), so the reference is meaningful without a dead relative link.
- `verify --compact` now budgets a quoted value ahead of the engine message, and never exceeds the 512-byte cap (#115, vsdd-cli v0.3.0 diagnostic-efficacy review item 8 part 2): a finding's quoted **value** block is now retained ahead of the lower-priority message prose, so a message placeholder can no longer outlive the value it points at (a dangling reference under tight budgets); the prose fills whatever budget remains.
